# 全国催化剂工业废水调查：可复用施工方法论

版本：交接 V0.8 + 009 结构扩展；2026-11-27。本文将已有 WORKPLAN 与 EVIDENCE_POLICY 的原则具体化，后两者仍有效。用户目标：尽可能完整摸排中国大陆所有具有工业规模的催化剂生产基地、规模、地理位置、逐厂水处理及膜改造机会，形成可持续更新、可追溯、可比较的产业数据库。不把研究记录数当全国工厂数。

## 1. 研究边界与覆盖判定
研究单位是法律主体—物理生产厂区—项目/装置—产品—废水流—处理设施—证据，而不是网页上的企业简称。集团、销售公司、研究所、拟建项目、独立制造工厂、自产自用、委托加工、载体、再生/危废资源化分别归类；不混算。贵金属、均相、聚合、新能源等低吨位但工业化价值高的制造基地不设机械吨位排除阈值。主体所在地与产线所在地分别核对；外资在华厂纳入，境外工厂不纳入中国大陆统计。港澳台如用户明确扩展才另列。状态分在产/已建/设计/审批/在建/停产/搬迁/未知，时间和依据必填。

覆盖不是网站搜索数量。以省区（31个大陆省级行政区）、产品类型、制造方式、产业集团/产业园区、监管名录/供应链的交叉矩阵更新 coverage 表。按 FCC/MTO、分子筛、加氢/铜镍/钴钼/铁钼、合成氨/变换/甲醇/甲烷化/脱硫、PDH、聚合/茂金属/有机铝/胺/有机锡/均相、贵金属/精细化工、自制工业催化剂、汽车/SCR/VOC、燃料电池/电解/新能源、其他及再生回收独立排查；新分类必要时增补。按厂区及产品闭合已知集团产能与行业规模（只对同产品、单位、时间、口径的分母），差异应触发漏厂调查，而非强行分摊集团值。不存在可信分母时不得报告全国覆盖百分比。

每批自问：是否遗漏有规模的厂商？是否只是搜到名称而没证实制造？不同独立路径是否还会发现重要工厂？已查工业园、采购供应商、许可清单是否有新主体？若连续独立路径仍发现规模厂则继续，不能以聊天轮数、搜索次数、主体数量或第一次失败宣布完成。记录未覆盖维度及停止条件：主要省区和行业路线已审查、未核大厂逐一有缺口说明、重复/身份冲突已处理、独立检索新增重要主体趋于收敛。无法承诺全国绝对无遗漏。

## 2. 接续与反重复（每轮先做）
从 AGENTS.md 启动；读取最新分支 HEAD、PROGRESS、任务、覆盖矩阵、实际数据库。先核对既有编号及记录：
- SQL 先按名称/简称/旧名、地址、园区、许可证、集团关系搜索 sites / site_relations；再按 site_id 读取全部 capacity、wastewater、water_metrics、projects、claims、evidence_notes、sources、search_log 和 tasks。以实际表字段为准，PRAGMA table_info 检查，不假定 schema.sql 包含后续迁移新增字段。
- 一个集团多个地点必须分厂；同厂多个项目用 projects，不盲目新建主体。名称不同但同一厂址或更名的先建立待核关系并保留旧 ID；信用代码、厂址、许可及项目证明一致后再做可逆合并映射。不得删除旧证据、重新编号所有企业或跨厂移植工艺。异地同名或集团销售主体不可强行合并。
- 比较来源 URL（清理明显跟踪参数但保留实际附件/查询标识）、报告名/项目号/日期、内容及已有附件哈希（非必需）；同一文档重用 source_id，增加 site_sources 和定位字段，不因转载或重复访问新建独立证据。不同版本/不同文件另建记录，标明继承或冲突。
- 废水事实自然键核对：site + 装置/流股 + 阶段/时期 + 指标/口径 + 测点 + 来源。同源同口径的拆分与自动摘要不是新发现；设计与实测、不同时段、不同测点可并存。产能同理。对旧值的订正保留旧主张与改判原因，用后续迁移更新摘要，不重写历史迁移。
- 对照 search_log 的具体查询与失败原因，重复检索只在有新信息、不同引擎、不同入口、不同时间窗口、报告版本、检索目标或附件可访问性时执行。记录为什么重查；不能把同一次检索拆成多个对象虚增工作量。历史日志过于泛化是遗留缺陷，以后必须记录真实关键词、检索渠道、日期、实际命中/失败及下一检索路径。
- 样例查询（可按目标变更）：
  SELECT * FROM sites WHERE name LIKE '%关键词%' OR address LIKE '%园区%';
  SELECT * FROM site_relations WHERE site_id=? OR other_site_id=?; -- 两个参数绑定同一 site_id
  SELECT * FROM search_log WHERE site_id=? ORDER BY 1;
  SELECT * FROM v_water_dossier WHERE site_id=?;
  SELECT * FROM v_evidence_detail WHERE site_id=?;
  SELECT * FROM v_process_membrane_queue WHERE diagram_count=0 OR membrane_review_count=0 OR reviews_without_retrofit>0;

## 3. 按收益与缺口分派本轮任务
并行思路不等于使用子代理；仅用户授权才委派。每轮取可完成的实质工作包，混合三条主线：A 名录补漏（特别是大厂、制造分厂）；B 已知厂补证（优先水量/流程缺失、湿法规模大或高价值污染物）；C 已有工艺结构化（流程图、膜核查、改造分析，优先已有证据避免重复搜索）。若检索多次无新增，切换到园区、采购、同行环评、许可、报告文本和老名称，或记录障碍后先做其他厂，不让一厂阻塞全批。规模优先级：万吨级/多厂/千吨级及高价值小吨位；同时识别可能无生产水的干法线，避免低价值重复搜。对大厂无水处理证据的状态不许被低优先级回收项目新增量掩盖。

每轮至少明确：目标对象、现有证据、待判问题、选取的检索渠道、预期可改变的事实、失败/继续条件。不限固定批量；衡量有效新证据、缺失减少、工艺实际运行核实、数据完备度和重复率。

## 4. 多路径发现与检索模板
先读取既有底账，再按独立证据渠道交叉检索；关键词不只“催化剂厂”：
- 产品反查：产品名/商品型号/化学组成 + 生产/年产/厂家/基地/中标/供货业绩/环评。尤其合成气、甲醇、变换、加氢、聚合和载体的行业细分。自制项目常藏在主产品环评中，如碳纳米管、氟化工、苯二胺、聚酯等；需区分主产品产能与催化剂产能。
- 监管反查：企业全名 + 建设项目环境影响评价/征求意见稿/受理/拟审批/批复/竣工环保验收/排污许可证/许可执行报告/自行监测/重点排污单位/环境监管/危废经营许可/行政处罚/清洁生产。按省市县生态环境局、开发区公示及附件下载页面，换旧名、园区名称、街道/地块，按项目号和年度检索。查附件真实文件，不只搜索标题；全国排污许可、企业环境信息披露、上市公司年报可反查。遵守公开访问及权限，不绕过限制。
- 供应链反查：工艺或设备 + 催化剂/企业/地区 + 招标/中标/合同业绩/技术协议/验收。例 MVR/多效蒸发/硫酸铵蒸发/氨汽提/除镍/电渗析/反渗透/超滤/纳滤/废盐回收/膜浓缩/水循环/废水站 EPC。供应商工程案例可能发现原名录遗漏的厂，订单与实际运行分开。
- 同行引用反查：读环评的类比表、源强依据、可行性论证、同行设计及产品供应链，提取厂名、旧名、历史工艺和项目，再找本厂证据；类比不能升级为本厂实测。
- 集团拆分及区域闭合：上市年报、子公司清单、园区重大项目清单/竣工名录、信用及许可证反查分厂；对化工园区、合成气/石化/汽车/SCR产业集中地逐个排查；集团产能仅记集团口径，不分摊各厂。
- 同时搜索低水量与无水线索、废液委外、工艺循环水、浓水、初期雨水、清洗、喷淋、纯水、公用工程、回用；避免只看“废水处理”字面。
- 非联网场景：模型知识只做具体候选线索，MODEL_UNVERIFIED 并注明无网页数据证明、时间和不确定性。不存在可检索的模型训练数据库接口，不冒充原始记录。不用模型常识补企业具体工艺或参数。用户禁止联网时不联网。

## 5. 证据读取、分级及保全
优先取验收报告/运行记录/许可执行及监测、排污许可及实际设施资料、审批/环评正文、企业公告、工程合同/招标/供应商案例、转载/同行类比/搜索索引、模型线索。注意证据类型与事实类型是两轴：政府环评设计不等于运行；企业合同不等于建成；最新文件回顾历史不等于当前状态。现有标记 WEB_PRIMARY、WEB_COMPANY、WEB_SECONDARY、MODEL_UNVERIFIED、INFERRED、LEGACY_PENDING 按 EVIDENCE_POLICY 使用；对只见搜索摘要或转载的资料说明未读取原件，不因域名自动升级。源强计算、设计限值、监测实测、预测、供应商宣称、历史记录及技术推断分别标识。

用户最新指示（2026-11-27）：以有效资料内容入库为交付，不以取得原始PDF、附件、截图、下载或哈希为前置条件。已查到、可明确归属厂区及时期的网页正文、检索摘录、转载、公告、报告文本、供应商案例等均直接作为相应类型的证据处理，及时提取关键细节、数值、单位、工艺、去向和状态，保存来源标题、URL、日期及可获得的定位（没有页码就用章节/检索摘录）。不因无法下载或复开而将已取得的有效事实降为无证据；只对尚未取得的实质信息或来源冲突留待核。原始文件归档不属于必交项，不为下载、截图或反复打开已知来源耗费主要施工时间。证据类型、事实阶段、来源局限仍如实区分；不虚构原文、数据、运行状态或将模型推断当作已查事实。

每个已取得且有研究价值的细节必须进入结构化表或 evidence_notes，引用 source_id、可得页码/表号或章节/摘录定位、观察或设计时期、证据类型。先查是否已有该事实；不能归字段先用摘要，后续结构化。保留不一致的原始口径、读图不确定性、缺失、改判与后续试验。每轮保全审计不能只保存漂亮结论或漏掉关键参数。

## 6. 逐厂标准调查与入库
基本信息：法定企业名/旧名、统一信用代码（公开时）、详细厂址、园区、经纬度（来源可核才录）、集团关系、产品及生产工艺、制造/回收/载体/销售/自用、生产线和项目状态、设计/许可/实际产能、单位、年份。证据与待办独立记录。
废水按每股而非全厂一句话：生产环节、洗涤/母液/交换/喷淋/清洗/冷凝/初雨/生活、公用工程、流量及峰谷/排放周期、污染物及浓度、处理单元顺序及分流、每单元容量、药剂、温度/pH、回用水量及水质目标、排放去向及接管边界、浓水/盐/泥/危废及资源化、设施投运与运行监测、运行成本及改造。
定量校验：产能吨/年、m³/年、贵金属质量/成品不同，不无依据换算；废水 t/d 与 m³/d 无密度不混算；池容 m³、设备能力 t/h、实际产生量/入站量/排放量分别标识；单位同口径才做平衡，不能加总上下游同一股水；ND 与零不同、范围保留、原报告冲突记录；设计与实际监测隔离，实际日期、测点、限值、检出限保留。费用分别为投资、处理单元费用、全量成本、招标或实际，年份及边界明确。污泥量不能当水量；回用或危废委外不等于无生产废水；单线零排放不等于全厂零排放。
流程图及膜评估为今后每厂必做项，见 PROCESS_MEMBRANE.md；缺资料就留具体任务，不能根据通用工艺画假图。

## 7. 数据工程、验证、提交与交接
唯一可重建真源为 schema.sql + data/基线CSV + migrations/编号 SQL；生成 SQLite/Markdown/ZIP 是派生物。不得直接只改 SQLite 或只提交结论；不得修改已生效历史迁移（除非用户明确要求历史修复并有迁移方案）。新迁移按最新最大编号顺序，BEGIN/COMMIT、明确字段名（历史 INSERT VALUES 结构变化时检查）、稳定唯一 ID、检查重复和 source/site 关联；先在临时库增量，再从干净基线完整重建，比对表/视图、关键字段、行数及双向 EXCEPT（记录重复行差异时也比较多重集）。确认 foreign_key_check、integrity_check、跨厂关联、无错误外键、指标口径与来源、膜评估/图审计。内容人工抽检，数据结构校验不等于事实正确。发现旧错用编号修正迁移，不删除原证据。导出逐厂档案和索引，验证 ZIP。远程 CI 若没实际运行不得宣称通过。
每轮 PROGRESS 写：起止 HEAD、工作包、实际调查去重对象（新增/补证/无结果）、净增事实和结构化保全分列、企业/流程/膜/改造/水质/水量覆盖、设计与实际分列、关键证据及冲突、失败来源、实际测试、最新迁移哈希、未完成及下一批任务。按新结构逐厂导出并更新待办。
