# 开发路线与验收任务（现行）

用户已批准应用开发总体方向。以可用的最小产品为目标，开发批次与研究迁移独立。下面编号是稳定任务ID，不是SQL或批次数。当前选取第一个未通过验收且无阻塞的任务；具体当前断点以PROGRESS为准。

| ID | 任务 | 验收 |
|---|---|---|
| A01 | 事实库结构审计与映射契约 | 实查31表/38视图及主键、证据、单位、版本；输出数据字典、跨层字段映射与异常清单，覆盖全部现存site_id，区分待核身份；可复跑统计，不能把375主体全当工厂 |
| A02 | 市场主体标准化 | 实现独立应用派生层/迁移及导入程序；集团/法人/厂区/项目多对多映射、别名与控制权历史；每个旧ID可追溯且无强制合并；重复导入幂等、冲突保留；先以可信证据核实所有制，不猜 |
| A03 | 生产/水流/设施结构 | 规范生产线、流股、测点、站、设备及共享关系；数量/单位/时期/阶段/上下游口径明确；所有原事实与来源可追溯；无法确认的映射独立待核；抽样校核 |
| A04 | 市场浏览可用数据接口 | 工厂详情、组织树、工艺历史、证据下钻、搜索/过滤；旧库同步增量、无损验证；不将候选当在产 |
| B01 | 可版本化技术能力及案例模型 | 定义适用条件、出水/浓水、成熟度、成本与资源边界，匿名合成案例测试；真实数据私有，未配置显示未知 |
| B02 | 多流股动态商机匹配 | 规则与版本可追溯，硬约束/未知/候选分开，一厂多商机，技术变更前后差异；分开技术、价值、可达、时机、可信度，不能伪造排名 |
| B03 | 采购路径与小公司风险 | 所有制独立于采购机制；直销/设计院/EPC/合作；现金流、付款、准入、保证、资源容量及风险；可配置偏好和解释，未知不默认零 |
| B04 | 技术经济情景 | 相同流股、阶段、单位、费用边界，客户节约与本公司利润/现金流分开；支持三情景与敏感性，未知不出虚假实际值；测试边界与负收益 |
| C01 | App最小产品基础 | 响应式Web/PWA、统一后台、测试数据及部署说明；用户与角色、服务端权限、私有数据隔离、备份恢复；禁止把机密导入公开库 |
| C02 | 客户与商机工作台 | 业务员搜索/客户档案/跟进/推荐接触路径；技术员流股参数/证据/类似案例/任务；共用商机状态，示例数据标记清楚 |
| C03 | 协同闭环 | 线索→资格→技术初筛→取样→小试→方案→报价审批→实施/验收→售后；共享缺口清单、负责人、下次行动、操作审计；无真实客户资料时使用匿名测试 |
| C04 | 管理及研发视图 | 项目优先级、人员负荷、风险与现金流；技术升级解锁市场及障碍聚类；区分市场潜力与真实销售进度 |
| C05 | 试用与发布验收 | 业务、技术、管理角色场景测试，移动/桌面、权限越权、备份恢复、可用性；在公司授权环境导入内部数据并验收，未获授权则留阻塞 |

## 持续任务
R01 定向补充所有制、实际采购主体、有效企业工作渠道及项目时机；R02 高价值流股证据、独立新原报告与新厂补漏；R03 对真实新需求核技术经济参数；R04 维护证据冲突和历史版本。保留原研究调度，不以私有数据缺口或固定项目数阻塞App；没有触发事件不重搜冷却轨道。

最新用户指示：横向批量覆盖全库，A02/A03定向补证与A04/B01/B02/C02/C03可用功能并行；不要求标准化全部厂区和测点后才开发。先做本地试用，再做必要多人权限及备份，不做极端防御或企业级审批。优先可交付功能而非预先实现全部复杂模型。真实技术边界、内部案例、资金阈值和私有部署由公司授权提供，缺失不阻塞公开代码/测试。未经实测不得标验收通过。
